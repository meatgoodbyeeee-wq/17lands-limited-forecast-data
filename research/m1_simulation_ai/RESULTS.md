# M1 結果: hybrid Simulation AI は、エンジン GIH を実測に近づけるか(MSH)

本番・Pages は変更なし。FRA は不使用。PLAN.md の事前登録どおり(`m1.py`、`log.txt`、`result.json`)。各条件 3,040 ゲーム(320 デッキ、同じデッキ・同じシード)。両条件で n≥100 の共通カードは 212 枚(MSH 278 枚中)。

**Rule M1: 不支持。** (a) が満たされなかった。

| 指標 | 通常 AI (C) | hybrid (H) | 差(H−C) |
|---|---|---|---|
| 打ち切り(120秒)ゲーム | 4(0.13%) | 25(0.82%) | |
| 信頼性(半分に分けた相関) | 0.765 | 0.702 | |
| スピアマン(e, 実測 a) | +0.411 | +0.445 | **+0.034、95%区間 [−0.070, +0.145]** |
| スピアマン(e, B10 残差) | +0.311 | +0.320 | |
| 1枚抜き CV MAE(p のみ 2.297) → p+e | 2.212 | 2.177 | −0.035pp |
| AA の e(順位/212) | +10.0(13位) | +6.6(24位) | |

判定: (a) Δρ の区間の下限 > 0 → **満たさない**(区間が 0 をまたぐ)。(b) H の MAE < C の MAE → 満たす(ただし 0.035pp と極めて小さい)。(c) H の打ち切り率 < 5% → 満たす(0.82%)。

## 読み方
- **hybrid が通常 AI より良いとは言えない。** 相関の差は +0.034 で、区間は [−0.070, +0.145]。「差がない」と示せたのではなく、このゲーム数では**小さな差を検出できない**。改善も悪化も、この範囲なら否定できない。
- **どちらの AI も、B10 だけより少し良い。** 両条件とも ρ(e, 残差) は約 +0.31(片側 p<1e-5)で、MAE は p のみ(2.297)より下がる。K1 の結論(エンジン GIH は B10 の外れを少し説明する)は、取り直した通常 AI でも再現した。ただし改善幅は小さい(通常 AI で 0.085pp、hybrid で 0.120pp)。
- **AA の順位は読まない。** K1 の通常 AI では e=+5.5(43位/228)だったが、今回の通常 AI では +10.0(13位/212)。同じ AI・同じ方法でも、ゲームが別なら AA の e が約 4.5pp 動く。この揺れの大きさでは、hybrid の AA(+6.6、24位)が良いか悪いかは判断できない。信頼性が K1 の 0.86 から 0.765 に下がっているのも、ゲーム数が約半分のためと整合する。
- **hybrid は信頼性がやや低い**(0.702 対 0.765)。先読みの探索に乱数が入り、同じカードでもゲーム間の差が大きいと考えられる(未検証)。
- **カード単位では大きく動くが、方向がそろわない。** 例: Thor, God of Thunder の e は −11.0 → +11.1(実測 a=+6.5)で実測に近づいた。一方、L 系列で通常 AI の誤りが見つかったカードは、hybrid で直らず、むしろ e が下がった(Super Suit −4.7 → −7.7、Visions of Villainy −7.8 → −13.1。実測 a は −0.5 と −2.4)。hybrid は、装備の対象判断や、インスタントのドローのタイミングを直す手段にはなっていない。

## 限界
- 試したのは **hybrid のみ**。full は、1ゲーム約 77 秒、ヒープ 1.5GB と 3GB の両方でメモリ不足、打ち切りが多発したため回せなかった(予備測定は `timing_pilot.txt`)。「Simulation AI 全般が効かない」とは言えない。
- 打ち切りゲームは除外した。H では 25 ゲーム(0.82%)で、長引く盤面のカードをわずかに落とす偏りがある。率は小さく、結論を変える大きさではない。
- ゲーム数は K1 の約半分で、e のノイズは K1 より大きい。K1 とは別のゲームなので、K1 の数値(228 枚)と直接は比べない(p のみの MAE も 2.264 と 2.297 で、カード集合が違う)。
- ランダム構築デッキ・1 セット(MSH)の限界は K1 と同じ。AA は e の選択に使っていない。
- PLAN からの変更はなし。ただし最初の予備測定で、総当たり経路にパッチが漏れて Simulation AI が効いていなかった(通常と完全一致)のを検出して直した。本番の 3,040 ゲームは、修正後の jar だけで回している。

## 検算
- **独立再計算**(`check_m1.py`、`m1.py` を使わず、順位相関とハット行列による 1 枚抜き CV で別実装): ρ(e,a) +0.411 / +0.445、ρ(e,残差) +0.311 / +0.320、MAE 2.297 → 2.212 / 2.177、Δρ +0.034 が一致。ブートストラップ区間は別シード・5,000 回で [−0.068, +0.144](本体は [−0.070, +0.145])。
- **再現性**: リモートの最新から新規クローンし、`python3 -I m1.py` を実行。`log.txt` と `result.json` がバイト単位で一致。

## 次の判断(あなたの判断)
- hybrid を他セットへ広げる根拠は、この結果からは得られない。
- 残る選択肢は、(1) full を少数のカードに絞って試す(1 ゲーム約 77 秒で、規模は大きく制限される)、(2) Simulation AI は止め、通常 AI の弱点を別の方法で補正する、のどちらか。どちらも、サキヨミ™の予測に使うかは別の判断になる。

## Opus 5.5 の所見(2026-10-21 追記。Sonnet 5.5 の結果を見直したもの)
上の結果と判定は変えない。以下は、その読み方と次の判断への意見。

**結論: Forge の AI 改良(full も、通常 AI の補正も)は保留にし、K3 の結果を待つ。その間はスタートレックの作業を優先する。**

1. **full を試しても、同じ弱点は直らない可能性が高い(コード確認 + 推定)。**
   - 確認したこと: hybrid と full は、同じ `GameStateEvaluator` の点数で盤面を比べる(`SpellAbilityPicker`、`SimulationController` から呼ばれる)。先読みの深さの既定は 3。
   - 確認したこと: 点数では、自分の手札は 1 枚あたり約 5 点、クリーチャーは例として 5/5 が約 225 点、クリーチャー以外のパーマネントは「50 + 30 × マナ総量」(オーラは 0)。
   - 推定(挙動の記録では未検証): 手札を引く価値が小さいので、ドロー呪文を相手のターンまで待つ理由が生まれにくい(Visions of Villainy)。装備先の有無を点数が見ないので、対象がなくても場に出すだけで点が上がりうる(Super Suit)。本結果で、この 2 枚の e が hybrid で下がったことと整合するが、原因の証明ではない。
   - full は深く読むだけで採点は同じなので、同じ誤りを繰り返すと見込む。1 ゲーム約 77 秒とメモリ不足のコストに見合わない。
2. **M1 は、小さな差を検出できない設計だった。** Δρ の 95% 区間の半幅は約 0.11 で、検出できるのは Δρ が 0.15 前後以上の差(ρ が 0.41 から 0.56 に上がる規模)だけ。現実的な改善幅ではない。事前登録の前に、検出力を計算しておくべきだった。「不支持」の結論は変わらないが、「判定できる設計ではなかった」という面がある。
3. **ノイズを割り戻した参考値(事前登録外、結論には使わない)。** ρ(e, a) を信頼性の平方根で割ると、通常 AI で約 0.47、hybrid で約 0.53。hybrid は情報がやや良く、ノイズが多い可能性を示唆するにとどまる。
4. **ボトルネックは AI の腕ではない可能性が高い。** ランダム構築の 23 枚でドラフトもない、という測り方が上限を決めている。ノイズを除いても ρ は 0.5 前後、誤差の改善は約 0.1pp(4〜5%)。K2 も M1 も判定できなかった。AI を改良しても、得られる価値の上限は小さいと見る。
5. **時間の使い方。** エンジン GIH を本番に入れる価値があるかは、K3(他セットへの一般化)が決める。AI の改良に意味が出るのは、K3 が通ってからになる。
6. **どうしても full を確かめたい場合の安価な方法。** GIH ではなく行動を見る。Super Suit と Visions of Villainy の使い方を、各 20 ゲーム前後記録すれば足りる。ただし上記 1 により、必要性は低いと見る。
