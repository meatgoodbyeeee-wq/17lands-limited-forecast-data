## 2. 環境シート(セット共通。そのセットのカードの判定入力すべての冒頭に1つ付ける)
スクリプト `env_sheet.py sheets` が `sheets/<SET>.txt` を作る。判定役には**セット名を言わない**。カードの色は W/U/B/R/G、金色(2色以上) `gold`、無色 `colourless`。レアリティ別の数は「C/U」(コモン+アンコモン)と「R/M」(レア+神話)の2群で、「C/U|R/M」の形。**判定中のカード自身のレアリティは見せない**(シートはプール全体の統計。`rare`/`mythic` という語は入力に出さない。`leakcheck` で確認)。

### 2.1 クリーチャーの質
色ごと(W U B R G 金色 無色)に、マナ総量 ≤1(0 を含む)・2・3・4・5・6+ ごとの枚数と平均 P/T、全体の枚数と平均 P/T。全カード版と C/U だけの版の2表。2マナ域の数は MV2 の列。P/T が `*` のカードは平均から除く(枚数には数える)。

### 2.2 除去の量と種類(相手のクリーチャーに使えるもの)
色ごとに、種類別の枚数とマナ総量の一覧を「C/U n (MV…) | R/M n (MV…)」で書く。1枚が複数の種類に当たれば両方に数え、`any` は重複なしの枚数。判定は本文(注釈文を除く)に対する固定の正規表現で、`env_sheet.py` の `removal_kinds` / `lockdown`:
- **destroy(破壊)**: `destroy target …`、対象がクリーチャー・土地以外のパーマネント・パーマネント(「クリーチャー or プレインズウォーカー」「アーティファクトかクリーチャー」も含む)。
- **damage(ダメージ)**: 「any target」「target creature」「creature or planeswalker」「up to N target creatures」「divided as you choose among」への ~ deals N damage。
- **exile(追放)**: `exile target …`(対象の条件は destroy と同じ)。「until ~ leaves the battlefield」型も含む。
- **bounce/tuck(バウンス・ライブラリー送り)**: `return target … to its owner's hand`、`put target … into/on top of/on the bottom of its owner's library`(クリーチャー・土地以外のパーマネント・パーマネントが対象。カード(墓地)は除く)。
- **−X/−X**: 対象クリーチャーに `-N/-M`(M≥1 または X)、または対象に −1/−1 カウンターを置く。
- **fight/bite(格闘・噛みつき)**: `fights`、`deals damage equal to its power to …`。
- **lock-down(拘束型。ユーザー追加指示)**: オーラなどでクリーチャーをタップし続ける・攻撃もブロックもできなくする・起動型能力を使えなくするカード。**オーラ、エンチャント(クリーチャーでないもの)、アーティファクト(クリーチャーでないもの)だけ**(インスタント・ソーサリー、クリーチャーカードは対象外)。次のどれか: (a) `enchanted creature / target creature / creatures your opponents control …can't attack`(「attack or block」を含む)、(b) `… doesn't untap during its controller's untap step`、(c) 起動型能力が起動できない(`activated abilities … can't be activated`)、(d) 繰り返し使うタップ能力(`…: tap target creature`、自分のクリーチャーを除く)。**相手のクリーチャーに使えるものに限る**: オーラは `Enchant creature`(`you control` 付きや土地・アーティファクト用は除く)、`enchanted creature gets +N/…` を与えるオーラ(利点つきの呪い)は除く。支配変更(コントロールを奪い攻撃・ブロック不可にする)型も、本文が (a)(b) を満たせば含む。
- **sweeper(全体除去、別枠)**: `destroy/exile all/each creatures`、`deals N damage to each creature`、`all/each creature gets -N/-N`(自分のクリーチャーだけを対象にするものを除く)、全体バウンス。
- **含めないもの(ユーザー指示)**: エンチャント除去(エンチャントを破壊・追放する帰化型)・アーティファクト除去・土地破壊など、対象にクリーチャーを含まないもの。「アーティファクトかエンチャント or クリーチャー」のようにクリーチャーを含む複数の対象は含める。
- **既知の誤差**: 一時的な追放(フリッカー)、ETB で自分用に使えるピンガー(クリーチャー本体の「any target」ダメージ)も機械的に除去に数える。判定結果を見て規則を変えない。

### 2.3 回避能力と受け手
クリーチャーカードの**自分自身の能力**で、次を回避能力とみなす(`evasion`): **飛行 flying、プロテクション系 `protection from …`、ブロックされない系 `can't be blocked`(条件つきの「…can't be blocked by creatures with power 2 or less」「…except by」を含む。「by more than one creature」は除く)、陰影 shadow、その他(fear、intimidate、horsemanship、skulk、〜walk)**。**威迫 menace は含めない(ユーザー指示)。トランプル(trample)も含めない。**受け手: 到達 reach と飛行(飛行を持つクリーチャーは飛行をブロックできる)。他のカードが飛行を与える(オーラ、装備品、全体強化)枚数も別に数える(`gains/has/have flying`)。色ごと・C/U|R/M で、クリーチャー数、種類別、any evasion、reach、ブロックできる枚数(飛行 or 到達)。

### 2.4 セットのメカニズム(中立ラベル)
4章を参照。ラベル、種別(キーワード/アビリティワード)、収録枚数(C/U 数、色別 C/U|R/M)、そのメカニズムを持つ最小マナ総量のカードの文(注釈文つき)を1つ載せる。

### 2.5 アーキタイプ(10の2色の組)
各組に、その組の**金色アンコモン**(色がちょうどその2色、レアリティ=アンコモン、土地を除く。マナ総量・本文の昇順で最大2枚)の本文(名前なし)と、それが指すテーマに**関与するカードの枚数と色**(C/U|R/M)を書く。
- **テーマの抽出**(金色アンコモンごとに優先順位順、組全体で最大3テーマ): ① セットのメカニズム(中立ラベル。金色の本文に名前がある) ② クリーチャー・タイプ(`sc_extract` の ctype 参照、support) ③ キーワード・カードタイプ・非クリーチャーのサブタイプ参照(`sc_extract` の keyword / cardtype / nc_sub、support) ④ 一般テーマ(固定5つ): +1/+1 カウンター、トークン、ライフ獲得(lifelink を含む)、墓地、生け贄。`chosen_type`(タイプを選ぶ)は組のテーマにしない。
- **関与の判定(機械的)**: `have` = そのカードがテーマに該当する(メカニズムを持つ/そのタイプのクリーチャー/そのキーワードを持つ/そのカードタイプ/そのサブタイプ(またはその生成)/一般テーマの語が本文にある)。`refer` = `have` でない他のカードで、その本文が同じテーマを `sc_extract` の依存の語(whenever、for each、gets +N、as long as、…)つきで参照している(②③のテーマだけ)。④とメカニズムは `have` だけ(本文に語がある=関与)。土地を除く、全レアリティを色別・C/U|R/M で数える。
- **規則で拾えない場合**: 金色アンコモンが無い組(過去28セット+FRA の 290 組のうち 33 組=11%)は「no gold uncommon in the list」と書く。金色アンコモンはあるがテーマが上の規則で抽出できない組(40 組=14%、例: タップ/アンアンタップ、飛行・先制などの付与、色のコスト)は、本文だけを載せ「no theme could be extracted」と書いて枚数は出さない。人手で補わない。1組あたり平均 1.4 テーマ。
- **既知の誤差**: ④の語一致は広い(「token」が出るカードをすべて数える)。ライフ獲得はライフを失う文を除かない。

### 2.6 クリーチャー・タイプ
上位10タイプ(クリーチャーカード数、同数は名前順): 枚数、色別 C/U|R/M、C/U の枚数。タイプ行にあるタイプだけ数える(Changeling の「全タイプ」扱いはシートでは数えない。カード個別情報の該当カードの数では数える)。

### 2.7 インスタント・タイミングの介入
色ごと、C/U|R/M で次を数える(`hand_kinds`):
- **instant**: インスタント・カード。**flash**: 瞬速を持つカード。
- **hand(手札から起動できる、盤面・戦闘に影響する能力)**: コストに「このカードを捨てる」(`Discard this card` / `Discard ~`)を含む起動型能力(チャネル型、FRA の「{3}{G}, Discard this card: Destroy target creature with flying」型、魂力型)。**既定で含めないもの**: サイクリング系キーワード(cycling、landcycling、typecycling)、効果が純粋な手札入れ替え・探索(ドロー、ライブラリー探索、占術、諜報、ライフ獲得、見る)だけの能力。
- **swap**: 忍術・Sneak 型(`return an unblocked attacker you control to hand` でこのカードを戦場に出す)。
- **cyc-trigger**: サイクリング/捨てたときに効果が出るカード(`When you cycle this card …`、`When you discard this card …`)。純粋なサイクリングは含めず、この誘発効果があるもののみ含める(既定の判断)。
- `any` は重複なしの枚数。判断: ユーザー指示の「盤面や戦闘に影響する手札からの能力を含め、純粋な手札入れ替えのサイクリングは含めない」に従う。

### 2.8 シートの長さ
29セットで **平均 約3,500 トークン、最大 約4,400 トークン、FRA 約4,000 トークン**(文字数÷3.6 の見積もり。数字が多いので±25%)。許容の目安は6,000トークン。超えた場合の縮め方(事前決定。現在の29セットでは発動しない): ①C/U だけのクリーチャー表を省く ②アーキタイプの `refer` の色内訳を合計だけにする ③2枚目の金色アンコモンを省く、の順。

## 3. カード個別情報(何かを参照するカードだけ)
旧計画の参照の定義(`sc_extract.py` の support 参照: クリーチャー・タイプ、タイプを選ぶ、キーワード、カードタイプ、非クリーチャーのサブタイプ)をそのまま使う。参照のあるカードにだけ、参照ごとに(最大3参照)次の2行を付ける。
1. `SET INFO:` 旧計画と同じ密度の1行(セット内の枚数、C/U の枚数、デッキでの期待枚数)。
2. `MATCHING CARDS:` **条件を満たすカードの中身**: 該当カード数(C/U 数)、マナ総量ごとの枚数、クリーチャーなら平均 P/T(C/U だけの平均も)、**代表的なコモン/アンコモンの文3枚**(名前なし。選び方は機械的: 該当するコモン/アンコモン(自分を除く)を (マナ総量, 本文) の昇順に並べ、**最小・中央・最大**の3枚。参照が2つ以上のカードは2枚(最小・最大))。例文は230字で切る。判定役への指示は RUBRIC_v2.md(「例文は推奨ではない」)。
トークンを作るだけの節、自己参照、コストとしての言及は参照にしない(旧計画 2.1 のまま)。参照のないカードには付けない。

## 4. メカニズム名の中立化(決定)
**決定: セット固有のメカニズム名は、シート・カード本文・金色アンコモン・例文のすべてで中立なラベル(`Mechanism A`, `Mechanism B` …)に置き換える。FRA にも、過去28セットにも、TRK にも同じ処理を適用する。**
- 理由: L1 で、過去セットの R/M の約3割が名前から当てられた(名前の再認は記憶に基づく)。シートにメカニズムの一覧を載せると、そのセットの識別が1行で可能になる(例: 「offspring, gift, valiant」は1セットしかない)。名前を残すとシートが漏れの経路を増やす。ラベルと本文を揃えないと、シートの説明とカードの対応が取れないので、シートだけでなくカード本文も置き換える。注釈文(リマインダー文)は残すので、ルールの意味は判定役に伝わる。
- 検出規則(機械的、`env_sheet.py detect_mechanics`): カード本文の各行で、(i) `Name — `(アビリティワード)、または (ii) キーワード+リマインダー文(括弧)の直前の語(最大3語、数字・マナ記号・固有名詞の手前で切る)を候補とし、**過去28+FRA の29セットのうち4セット以下に出現し、そのセットで3枚以上に出現するもの**をそのセットのメカニズムとする。除外: 毎セットに出る基本のキーワード(flying、deathtouch、ward、…、cycling 系、equip、kicker、crew、scry、surveil、flashback)と、複数セットで繰り返し出る語は中立化しない。置換は語境界一致(`s/ed/d/ing` の活用つき)。
- 検出例(MSH: teamwork / FRA: empower, prepared, threshold)。全セットの一覧は `mechanics.csv`(セット、ラベル、実際の名前、収録枚数)。
- 代償・限界: ①旧 C9 判定は本物の名前で行ったので、新旧の差には「ラベル化の影響」が混ざる(評価で測れない。新しい方が不利になる向きの交絡)。②基本のキーワードや、検出されなかった語(4セットを超えて出る返り咲きの語、1〜2枚しかないメカニズム)は残る。③クリーチャー・タイプ(Kithkin、Hero など)とカード本文の固有名詞(Jace など)は残る。これらは旧 C9 と同じ露出。④TRK でも同じ検出を11/1に走らせ、検出の漏れ・誤検出が見つかった場合は、判定前に固定した例外リストをコミットして直す(判定結果を見て直さない)。

## 5. 検証範囲
判定の単位は**(セット, カード)**(シートがセットごとに違うので、同じ文の再録も別セットなら別入力)。
- **FRA**: 全カードの 288 枚(`cards.csv` の FRA 290 枚から、テキストのないバニラクリーチャー 2 枚(auto。旧計画どおり既定値)を除く)。土地の扱いは旧計画どおり: テキストのある土地 10 枚(「プレインズウォーカーがいなければタップ状態で出る」デュアルランド)と他の土地は判定する。基本土地は FRA 一覧に含まれない。
- **過去28セット**: ①**タイプを参照するカード(ctype + chosen_type の support 参照)637 枚(全数)** ②**それ以外(参照なし+タイプ以外の参照)から 300 枚**: セット×レアリティ(4段階)の112セルに**比例配分**(最大剰余法)し、セル内を `random.Random(20261023)` で無作為抽出(セルのキーは昇順に整列、`g1v2.py sample`)。比例配分なので②は母集団を代表する(重みづけ不要)。バニラ(auto)と基本土地は除く。実際の枚数は 637(旧計画の「ユニーク文 633」はセットをまたいだ重複を除いた数。v2 は(セット,カード)単位なので 637)。
- 合計 1,225 件 × 3 パス = **3,675 件**。一覧は `units.csv`(通し番号 n、セット、key、群 fra/type_ref/other、旧 GRADE、レアリティ)。`units.csv` に実測は入れない。過去セットの実測と旧 GRADE の取り出しは `past_pool.csv.gz`(過去28セットのみ)から、評価スクリプトが結合する。

## 6. 判定の手順(3パス)
- 判定モデル: `claude-opus-5-5`(C9・L1 と同じ。`claude -p --model`、ツール・MCP 無効、空ディレクトリ、1バッチ1呼び出し)。**Opus 3パス、独立**(各パスは別のエージェント、他のパスの出力を見ない)。
- 入力: `input_v2/<pass>/<SET>_<k>.txt`(36バッチ/パス、計108)。1ファイル = その**セットのシート + カード(最大60枚)**。ルーブリックは `RUBRIC_v2.md`。FRA は 288 枚を5バッチ(各58枚前後)。
- 順序: 各セットのカードを p1 = 通し番号の昇順、p2 = 逆順、p3 = 乱数順(seed 20261026+セット名の文字コード和)。バッチ分割は並べ替えた後。
- カード名は「~」、セット名・レアリティ・17Lands の数字は渡さない。「過去の知識を使わない」条件(ルーブリック冒頭)は維持。
- **機械的な確認 `g1v2.py leakcheck`(判定前に実施済み、現状ハードヒット 0)**: 入力に、そのセットのカード名(注: 本文中に引用されている名前=トークン名、クリーチャー・タイプだけの名前は許容)、セット名・セットコード(FRA など)、`rare`/`mythic`、17Lands の語(GIH、ALSA、win rate 等)、中立化したはずの実際のメカニズム名が無いこと。他セットのカード名のうち、ルール語と一致するもの(Flashback など 61 件)は情報として数えるのみ。
- 出力形式は C9 と同じ(1行 `<id> <IMP> <UNA> <VAL> <FLOOR> <FLEX> <PLAY> <GRADE>`、`raw_v2/<pass>/<batch>.txt`)。検証 `g1v2.py check`(形式、範囲、全カードの回答、重複・余分なし)。
- 特徴量: 3パスの平均・母標準偏差・3つの和(IMP+UNA、VAL+FLOOR、GRADE−1.25·PLAY)を C9 と同じ式で作る。

## 7. 評価の設計(事前登録)
共通の定義(D1 と同じ): `act_rel = actual_gih − そのセットの actual_gih 平均`(auto を除く全レアリティ、単位 pp)。**GRADE のずれ**: `act_rel ~ a + b·GRADE` の単回帰を、**評価セットを除く27セット**で当てはめ(LOSO)、`ずれ = act_rel − (a + b·GRADE)`。当てはめは**層ごと**(R/M、C/U)。新旧とも**同じカード・同じ手順**で当てはめる(旧 GRADE は `c9_features` の3パス平均、新 GRADE は v2 の3パス平均)。大きさは `|ずれ|` の平均で比べる。CI は**セット単位ブートストラップ**(28セットを復元抽出、10,000回、seed 20261028、percentile、ずれは LOSO 当てはめ後の値を固定)。

### 7.1 過去セットの再判定カードで、新旧の GRADE を比べる(判定の後、FRA の採点より前に実行)
- 同じカードの旧 GRADE と新 GRADE について、`act_rel` との**Spearman**(セット内の順位でなく、層ごとにセットを込みにした順位相関)と**Pearson**、`|ずれ|` の平均を比べ、差(新−旧)とセット単位ブートストラップ CI を出す。
- 切り口: **R/M と C/U**、**タイプ参照(637、全数)と非参照(300、無作為標本)**。非参照標本は比例配分で母集団を代表する。さらに SET INFO ありのカード(タイプ以外の参照を含む)・なしのカード。
- **主指標**: 層ごと(R/M、C/U)で、タイプ参照 637 枚の Spearman の差と `|ずれ|` の差。副: 無作為 300 枚の同じ指標。

### 7.2 新旧の尺度のずれと換算
- 新ルーブリック+シートで全体の水準が動く(例: 全体に高く/低く付く)可能性があるので、**新→旧の換算**を事前に決める: 7問それぞれ(IMP UNA VAL FLOOR FLEX PLAY GRADE)について、過去セットの**非参照の無作為標本のうち SET INFO が付かないカード**(約 270 枚)の3パス平均で、`旧 = α + β·新` の**線形(OLS)**を当てはめる。**評価対象のセットを除いて(LOSO)**当てはめ、そのセットのカードに適用する(過去セットの評価用)。FRA には**過去28セット全部**で当てはめた式を適用する。値は 0〜各上限にクリップ。
- 換算後の7問の平均から、SD 列は `β·SD_新`、和の列は換算後の平均から C9 と同じ式で作り直し、B10 の C9 の17列を**全 FRA カードで**置き換える。B10 の学習済みモデル(過去28セット、今の C9 のまま)にそのまま入れて FRA を予測(`g1v2` の凍結スクリプトで B10 を同じ環境で再計算し、案0の凍結済み予測と一致することを先に確認)。
- **換算前の値の予測も同時に作って報告する**(判定は換算後で行う)。換算式(α, β, 当てはめ件数)と、新旧の平均・分散の差を報告する。

### 12.1 評価スクリプトの解釈の固定(実装時に決めた点。判定前にコミット)
7.1〜7.4 の文面で幅のあった点を、`g1v2_eval.py` では次のとおり実装する。ユーザーが違う解釈を望むなら判定前に指示する。
- **当てはめに使うカード**: 回帰 `act_rel ~ a + b·GRADE`(LOSO)は、再判定した過去セットのカード 937 枚(評価セット以外の27セット、層ごと)で当てはめる。新旧とも同じカード。R/M = rarity_ord ≥ 2、C/U = rarity_ord ≤ 1。`act_rel` の基準になるセット平均は過去セット全カード(バニラ auto・基本土地を除く)の平均。
- **Spearman**: 層ごとに、セットを込みにした 1 本の順位相関(GRADE と act_rel)。P3 の「全体」は 300 枚全部(層を分けない)。
- **P4**: 「上がったカード」の割合を、(a) 937 枚全体、(b) タイプ参照 637 枚、(c) 無作為 300 枚で出す。**合否に使うのは (a) と (b)**(「全数」)で、(c) は報告のみ(件数が少なく偶然で動くため)。基準率は 937 枚全体の割合。上がったカードが 0 枚なら P4 は合格(該当なし)とする。
- **換算の当てはめ**: 7.2 のとおり(無作為 300 枚のうち SET INFO の付かないカード、7問それぞれ、LOSO)。FRA 用(過去28セット全部)の式は `eval_v2/conversion_all28.json` に出す。FRA の予測の凍結(B10 の再計算、8章)は判定後に別スクリプトで行う(未作成)。
- **ゲート**: `g1v2_eval.py` は `eval_v2/past_gate.json`(P1〜P4 の真偽と全体の合否)を出す。FRA の判定はこれが全合格のときだけ行う。

### 12.2 判定の実行方法(ユーザー決定、2026-10-23。判定の前に追記)
- **方法**: Claude Code CLI `claude -p`(旧 C9 と同じ経路。このセッションの CLI 2.1.309)。モデル `claude-opus-5-5`、effort・温度は CLI の既定(指定しない)。実行スクリプト `run_v2.py`。

- **範囲**: まず過去28セットの 31 バッチ × 3 パス(FRA の 5 バッチ × 3 は 12 章 3 のとおり P1〜P4 合格後)。
